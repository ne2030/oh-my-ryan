# 레포 분석 연결 규칙

## 핵심 원칙

기존 `analyze-source`의 연결 규칙(insights/_templates/ 참조)을 동일하게 따르되, 레포 분석 고유의 연결 유형을 추가한다.

## 의미적 관계 유형 (기존 5종 + 레포 전용 2종)

### 기존 유형 (그대로 적용)

| 관계 유형 | 설명 |
|-----------|------|
| **보완 (How↔Why)** | 하나는 "어떻게", 다른 하나는 "왜"를 다룸 |
| **대조 (vs)** | 같은 주제에 대해 다른 입장/접근 |
| **확장 (→)** | 하나가 다른 하나의 구체화/심화 |
| **선후 (時)** | 시간축에서 전후 관계 |
| **적용 (⇒)** | 하나의 인사이트를 다른 맥락에 적용 |

### 레포 전용 추가 유형

| 관계 유형 | 설명 | 예시 |
|-----------|------|------|
| **구현 (Impl)** | 기사의 주장/패턴이 레포에서 실제 구현됨 | 기사: "이벤트 드리븐이 좋다" → 레포: 실제 이벤트 드리븐 구현 |
| **동일 패턴 (≡)** | 두 레포가 같은 아키텍처 패턴을 사용 | bmad: Hub-spoke ≡ omc: Hub-spoke (구현은 다름) |

## 연결 대상별 규칙

### 레포 ↔ 레포
- **동일 패턴 (≡)**: 같은 패턴 카테고리에서 같은 패턴을 사용
- **대조 (vs)**: 같은 문제에 대해 다른 패턴/철학으로 접근
- **보완 (How↔Why)**: 하나는 프롬프트 중심, 다른 하나는 코드 중심으로 같은 목표 달성

### 레포 ↔ 기사
- **구현 (Impl)**: 기사에서 언급한 패턴/원칙이 레포에서 실제 구현됨
- **확장 (→)**: 기사의 아이디어를 레포가 더 구체화
- **적용 (⇒)**: 기사의 인사이트가 레포의 특정 기능에 적용됨

### 레포 → 카탈로그
- 레포의 patterns.md에서 추출된 패턴은 자동으로 `insights/catalogs/patterns.md`에 등록
- 카탈로그에서 레포 상세 분석으로의 wikilink 포함

## 연결 작성 형태

```markdown
## 관련 노트

- [[insights/analysis/{project}-repo-analysis|{project} DNA]] — 동일패턴(≡): 두 프로젝트 모두 Hub-spoke 오케스트레이션을 사용하지만 구현 방식이 다르다.
- [[insights/analysis/harness/2026-03-06-omc-v470-release|OMC v4.7.0]] — 구현(Impl): 이 기사에서 소개한 이벤트 드리븐 아키텍처가 실제 코드에서 어떻게 구현되었는지 확인.
```

## 연결 불가 판정

기존 규칙과 동일:
- 같은 도메인(AI 하네스)이라는 이유만으로 연결하지 않는다
- "둘 다 에이전트 오케스트레이션을 다룬다" 이상의 구체적 관계를 설명할 수 없으면 연결하지 않는다
- 연결이 없으면 "현재 연결 가능한 노트 없음"으로 표기

## 역방향 링크

새 레포 분석 노트를 생성할 때, 연결 대상으로 선정된 기존 노트의 "관련 노트" 섹션에도 역방향 링크를 추가한다.
