# 평가 루브릭 통합 참조

> self-improve 스킬이 eval/regression 수행 시 참조하는 통합 루브릭.
> v2: assertion 매핑 추가 — 객관적 부분은 evals.json으로, 주관적 부분은 grader claims로 분리.

---

## assertion ↔ 루브릭 매핑

각 루브릭 항목이 어떻게 검증되는지 정리한 표. eval 모드에서 grader가 assertion 체크 후, claims를 루브릭 채점의 evidence로 활용한다.

### analyze-source 매핑

| 루브릭 항목 | assertion으로 검증 가능한 부분 | 주관적 판단 필요 부분 |
|---|---|---|
| 인사이트 유용성 | 핵심 인사이트 섹션 존재, 3계층(원칙/사례/프레임) 중 2개 이상 구분 | 원본 없이도 핵심 파악 가능한 정도 |
| 계층 분류 자연스러움 | 원칙/사례/프레임 각각 1개 이상 존재 | 분류의 적절성, 경계 사례 판단 |
| 실행 가능성 | 하네스 적용 제안 섹션 존재 | 구체적 방향 제시 정도, 실행 가능성 |
| 근거 충분성 | URL 포함 여부 (B/C 깊이), 출처 개수 | 검증 품질, 출처의 신뢰성 |
| 연결 의미성 | wikilink 1개 이상 존재, index.md 등록 | 연결의 실질적 의미, 맥락 제공 정도 |

### analyze-repo 매핑

| 루브릭 항목 | assertion으로 검증 가능한 부분 | 주관적 판단 필요 부분 |
|---|---|---|
| 설계 파악도 | DNA 4개 파일 생성, 하네스 시사점 섹션 존재 | 요약만으로 프로젝트 핵심 파악 가능한 정도 |
| 패턴 구체성 | 구현 위치(파일 경로) 포함 여부 | 패턴 기술의 구체성, 맥락 설명 |
| 교차 연결 | DNA 파일 간 wikilink 존재 | 연결의 유기성, 철학→패턴 설명 |
| 비교 가능성 | 카탈로그 등록 여부, 동일 카테고리 구조 | 실제 비교 시 호환 정도 |

## analyze-source 루브릭

5항목, 각 1-5점. 기준선: 평균 3.5

### 1. 인사이트 유용성
원본을 읽지 않아도 핵심을 파악할 수 있는가.

| 점수 | 기준 |
|------|------|
| 5 | 원본 없이도 핵심 논지와 맥락 완전 파악 가능. 원본을 읽을 필요가 없을 정도 |
| 4 | 핵심 파악 가능하나 일부 뉘앙스는 원본 참조 필요 |
| 3 | 대략적 방향은 알 수 있으나 구체적 내용은 원본 필요 |
| 2 | 핵심이 불명확하거나 누락된 중요 포인트 있음 |
| 1 | 원본을 읽어야만 내용 파악 가능 |

### 2. 계층 분류 자연스러움
원칙/사례/프레임 구분이 모호하지 않은가.

| 점수 | 기준 |
|------|------|
| 5 | 각 항목이 정확한 계층에 배치, 재분류 여지 없음 |
| 4 | 대부분 적절하나 1-2개 경계 사례 존재 |
| 3 | 분류가 대체로 맞지만 혼동되는 항목 있음 |
| 2 | 여러 항목의 계층이 부적절 |
| 1 | 분류가 거의 무의미하거나 임의적 |

### 3. 실행 가능성
하네스 적용 제안이 구체적 방향을 제시하는가.

| 점수 | 기준 |
|------|------|
| 5 | 즉시 실행 가능한 구체적 제안 + 적용 컨텍스트 명시 |
| 4 | 구체적이나 세부 조정 필요 |
| 3 | 방향은 맞으나 추가 구체화 필요 |
| 2 | 추상적이거나 일반론에 그침 |
| 1 | 제안 없거나 실행 불가능 |
| N/A | `harness_applicable: false`인 노트는 이 항목 평가 제외 (평균 계산에서도 제외) |

### 4. 근거 충분성
(B/C 깊이) 검증에 출처 URL이 포함되어 있는가.

| 점수 | 기준 |
|------|------|
| 5 | 모든 핵심 주장에 검증 가능한 출처 + 구체적 데이터 |
| 4 | 대부분 출처 있으나 1-2개 미검증 |
| 3 | 일부 출처 있으나 핵심 주장 중 미검증 존재 |
| 2 | 출처 부족, 대부분 검증 없음 |
| 1 | 출처 전무 |
| N/A | A 깊이는 이 항목 평가 제외 (평균 계산에서도 제외) |

### 5. 연결 의미성
관련 노트 연결이 실질적 의미가 있는가.

| 점수 | 기준 |
|------|------|
| 5 | 모든 연결이 구체적 관계 설명 + 읽기 맥락 제공 |
| 4 | 대부분 의미 있으나 1-2개 형식적 연결 |
| 3 | 관련성은 있으나 연결의 의미가 불명확 |
| 2 | 태그 기반 기계적 연결이 대부분 |
| 1 | 연결 없거나 무의미 |

## analyze-repo 루브릭

4항목, 각 1-5점. 기준선: 평균 3.5

### 1. 설계 파악도
요약만 읽어도 프로젝트의 핵심 설계와 철학을 파악할 수 있는가.

| 점수 | 기준 |
|------|------|
| 5 | 요약으로 프로젝트 핵심 완전 파악, 코드 탐색 불필요 |
| 4 | 핵심 파악 가능하나 세부 구현은 상세 파일 참조 필요 |
| 3 | 대략적 방향은 알 수 있으나 설계 의도 일부 불명확 |
| 2 | 핵심 설계가 누락되거나 불명확 |
| 1 | 요약이 프로젝트 파악에 도움 안 됨 |

### 2. 패턴 구체성
패턴이 구현 위치와 함께 구체적으로 기술되어 있는가.

| 점수 | 기준 |
|------|------|
| 5 | 모든 패턴에 파일 경로 + 구현 방식 + 사용 맥락 |
| 4 | 대부분 구체적이나 1-2개 패턴 위치 불명확 |
| 3 | 패턴 자체는 맞지만 구현 위치 누락 다수 |
| 2 | 추상적 패턴 나열, 구현과 연결 부족 |
| 1 | 패턴이 일반론에 그침 |

### 3. 교차 연결
철학↔패턴↔기능맵 간의 연결이 자연스러운가.

| 점수 | 기준 |
|------|------|
| 5 | 모든 DNA 컴포넌트가 유기적으로 연결, 왜 그 패턴인지 철학에서 설명 |
| 4 | 대부분 연결되나 일부 고립된 항목 존재 |
| 3 | 연결은 있으나 피상적 |
| 2 | 연결 부족, 각 컴포넌트가 독립적 |
| 1 | 연결 없음 |

### 4. 비교 가능성
다른 프로젝트 분석과 나란히 놓았을 때 같은 관점으로 비교 가능한가.

| 점수 | 기준 |
|------|------|
| 5 | 동일한 카테고리/프레임으로 즉시 비교 가능 |
| 4 | 대부분 비교 가능하나 일부 카테고리 불일치 |
| 3 | 비교는 가능하나 재구성 필요 |
| 2 | 구조가 달라 비교 어려움 |
| 1 | 비교 불가능 |
