# 관련 노트 연결 규칙

> v2 부터 분석 노트는 트랙별 폴더에 저장된다. wiki 링크 경로가 `insights/analysis/{track}/파일명` 형태로 바뀐다.

## 핵심 원칙

**태그가 같다는 것만으로는 연결하지 않는다.** 의미적 관계가 있어야 한다.

**트랙이 다른 노트 간 연결을 오히려 권장한다.** 같은 트랙끼리만 연결되면 지식 지도가 3개로 쪼개진다. 트랙은 관점이고, 좋은 인사이트는 관점을 교차할 때 나온다.

## 연결 조건 (AND — 둘 다 충족해야 연결)

1. **주제 겹침**: 공유 태그 1개 이상 OR 동일 현상의 다른 층위를 다룸
2. **의미적 관계 유형 1개 이상**: 아래 표에서 해당하는 관계가 있어야 함

## 의미적 관계 유형

| 관계 유형 | 설명 | 예시 |
|-----------|------|------|
| **보완 (How↔Why)** | 하나는 "어떻게", 다른 하나는 "왜"를 다룸 | Park(How: AI 개발 방법) ↔ Lee(Why: 시장 변화) |
| **대조 (vs)** | 같은 주제에 대해 다른 입장/접근 | A(RAG 기법 중심) vs B(데이터 클렌징 중심) |
| **확장 (→)** | 하나가 다른 하나의 구체화/심화 | 원칙 글 → 그 원칙의 구현 사례 |
| **선후 (時)** | 시간축에서 전후 관계 | 2024년 예측 → 2026년 결과 |
| **적용 (⇒)** | 하나의 인사이트를 다른 맥락에 적용 | 이론 ⇒ 하네스 적용 사례 |
| **교차 (×)** | 트랙이 다른 노트가 같은 현상을 다른 렌즈로 보는 경우 (v2 신규) | model 트랙 논문 × ax 트랙 도입 사례 |

## 트랙 간 교차 연결 (권장)

지식 지도가 풍부해지는 대부분의 순간은 트랙을 가로지를 때 발생한다.

- `harness` ↔ `model`: 모델의 한계가 하네스 설계의 전제가 되는 순간 (예: 컨텍스트 윈도우 제약 → 점진적 공개 패턴)
- `harness` ↔ `ax`: 1인 하네스가 조직 단위 AX로 확장되는 순간 (예: 개인 SKILL.md → 팀 SOP)
- `model` ↔ `ax`: 기술 변화가 조직 구조를 바꾸는 순간 (예: 에이전트 자율성 → 직무 재분배)

## 연결 불가 판정

아래 경우에는 연결하지 않는다:

- `#agent` 같은 범용 태그만 공유하고 내용적 관계가 없는 경우
- 같은 분야라는 이유만으로 연결 (예: 둘 다 AI 관련이니까)
- 연결 설명을 쓸 때 "둘 다 ~에 대해 다룬다" 이상의 관계를 설명할 수 없는 경우

## 연결 작성 형태

```markdown
## 관련 노트

- [[insights/analysis/{track}/파일명|표시명]] — [관계유형]: [1-2문장으로 구체적 관계 설명]
```

예시 (트랙 교차):
```markdown
- [[insights/analysis/model/2026-04-07-kiwoong-yeom-harness-illusion|Yeom — 하네스의 민낯]] — 교차(×): model 트랙의 이 글이 제기한 "하네스 ≠ 지능"이라는 메타 경고는, harness 트랙의 Lopopolo 실전 사례와 나란히 읽어야 "작동하는 하네스"와 "지능처럼 보이는 환상"을 구분할 수 있다.
```

## 연결 대상이 없을 때

```markdown
## 관련 노트

- 현재 연결 가능한 노트 없음. 태그: `#tag1`, `#tag2` — 향후 동일 태그 노트 추가 시 검토.
```

억지로 연결하는 것보다 "없음"이 낫다.

## 역방향 링크

새 분석 노트를 생성할 때, 연결 대상으로 선정된 기존 노트의 "관련 노트" 섹션에도 역방향 링크를 추가한다. 트랙이 달라도 동일.
