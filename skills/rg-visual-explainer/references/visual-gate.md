# Visual Explainer 품질 검수 게이트

시각화를 생성하거나 수정한 뒤에는 먼저 `node <skill-root>/scripts/lint-visuals.mjs <파일>`로 자동 린트(위반 0건)를 통과시키고, 이어서 **수정한 모든 항목(샘플링 금지)**을 실제 브라우저(Playwright 등)로 렌더링한 스크린샷을 찍어 아래 항목을 눈으로 검수한다.

## 1. 1장면 콘티(`<desc>`) & 유형별 구조 적합성
- [ ] `<desc>`가 도형 부품 배치 명세서가 아니라 **독자가 깨닫는 단 하나의 핵심 장면·대비**로 쓰였는가?
- [ ] **(원인 해부 시)** “지금 어디서 왜 깨졌는가”에만 집중하고 해결안을 같은 그림에 Y자로 섞지 않았는가? 원인이 2개 이상이면 `[현상 + 원인별 독립 도식]`으로 분해했는가?
- [ ] **(아키텍처·현장 프로세스 시)** 추상 단계 박스 일렬 나열(`A→B→C→D`) 대신 실제 입력 1건의 변환·분기·트리 또는 물리 사물·작업자·공간 배치로 표현했는가?
- [ ] **(수치·비교 시)** 축·기준선·비율 막대·점 격자·포함 경계로 길이·위치 자체가 의미를 말하는가?

## 2. 글·그림 역할 분리 & 중복 제거
- [ ] SVG 내부에 서술 문장이나 3줄 이상의 텍스트 카드가 없고, 짧은 명사구·실제 값·기호만 남겼는가?
- [ ] 화살표·하위 영역이 이미 보여주는 내용을 위쪽 박스에 중복 표기하지 않았는가?
- [ ] 원리·원인 설명 자리에 상태 요약 HTML 카드로 도망치지 않았는가?

## 3. 구체적 사례 & 정돈된 기하
- [ ] 추상 플레이스홀더(`이름 A`, `항목 1`)나 내부 식별자·시험 번호를 번역 없이 넣지 않았는가?
- [ ] 무의미한 다중 래퍼 테두리나 맥락 없는 장식 기호 남발이 없는가?

## 4. 텍스트·도형 충돌 0건
- [ ] 글자·테두리·화살표 선이 1px도 겹치거나 잘리지 않는가?

## 5. 의미 색상 일치 & 강조색 절제
- [ ] 빨간색을 사방에 난무시키지 않고 핵심 결함·강조 1~2곳에만 절제했는가?
- [ ] 부정적 결론(위법·초과·삭제)을 정답이라는 이유로 초록색으로 칠하지 않았는가?

## 6. 자연스러운 읽기 흐름 & 본문 중복 방지
- [ ] `[짧은 도입 문단 <p>] → [시각 도식 <figure>] → [핵심 캡션 <figcaption>]` 흐름이 자연스럽고, 본문과 도식이 똑같은 단어를 단순 반복하지 않는가?

## 7. 독자 반문 테스트 (Cold-Reader "So What?" Gate)
배경을 모르는 독자 눈으로 읽었을 때 아래 반문이 하나라도 떠오르면 보완한다:
- [ ] **"그래서 이게 왜 문제이고 / 왜 이 구조가 필요한 건데?"**
- [ ] **"저 전제나 용어·약어가 도대체 무슨 뜻이야?"**
- [ ] **"이 그림 없이 위 본문만 읽는 것과 무슨 차이가 있어?"** (그림이 글보다 빠른 시각적 가치를 주는가?)
