# Visual Explainer 품질 검수 게이트 (v1.2.0)

시각화를 생성하거나 수정한 뒤에는 먼저 `node <skill-root>/scripts/lint-visuals.mjs <파일>`로 자동 린트(위반 0건)를 통과시키고, 이어서 **수정한 모든 항목(샘플링 금지)**을 실제 브라우저(Playwright 등)로 렌더링한 스크린샷을 찍어 아래 8가지 항목을 눈으로 검수한다. 하나라도 위반되면 즉시 수정하고 재검수한다.

## 1. 1장면 콘티(`<desc>`) · 문제/해결 분리 · 다중 원인 분해 (Story-First & Separation Gate)
- [ ] `<svg>` 안의 `<desc>`가 도형 부품 배치 명세서(“초록 체크, 찢긴 점선, 원형 점 10개...”)가 아니라 **독자가 단박에 깨닫는 ‘단 하나의 핵심 사건·어긋남 장면’**으로 쓰였는가?
- [ ] **문제 vs 해결 분리**: 원리·원인 도식이 “지금 어디서 왜 깨졌는가”에만 100% 집중하고 있으며, 같은 그림에 `게이트 적용 시 / 목표 화면 / 고친 뒤` 같은 해결안을 Y자로 섞어 헷갈리게 만들지 않았는가?
- [ ] **다중 원인 분해**: 핵심 원인이 2개 이상일 때 1개 그림에 구겨 넣지 않고 **`[간단한 전체 현상 1개] + [원인별 독립 도식]`**으로 분해했는가?
- [ ] 원리·원인을 설명하는 자리에 “구현 완료 / 기준 미정 / 체크리스트” 같은 상태 요약 HTML 카드로 도망치지 않았는가?
- [ ] 도형의 위치·길이·빈 구멍·단절 자체가 의미를 말하고 있으며, 박스를 피하려다 톱니 테두리·과녁 아이콘 등 요상한 장식 기호를 남발하지 않았는가?

## 2. SVG 문장 금지 & 장식용 래퍼 박스 금지 (No Prose & No Wrapper Nesting Gate)
- [ ] SVG 내부에 서술형 문장(`"~하기 때문에 ~한다"`)을 넣지 않고 **2~14자 내외의 짧은 명사구·실제 사례명·필드명·수치**만 남겼는가? (이야기와 인과 설명은 HTML `<p>`, `<figcaption>`으로 분리되었는가?)
- [ ] 텍스트 박스를 묶기 위한 **무의미한 장식용 외곽 테두리 중첩(Wrapper Box-in-Box)**이 없는가? (단, 장면 뷰포트 안의 지형/경로/카메라, 미니 화면 프레임 안의 필터 바/목록/미니 그래프, 데이터 레코드 안의 필드 슬롯, 집합 범위 안의 사건 점 등 **구체적 대상을 묘사하는 내부 구성요소**는 정당한 표현이다.)
- [ ] 화면에 `"독자 질문:"`, `"이 도식이 답하는 질문:"` 같은 메타 라벨을 노출하지 않았는가?

## 3. 구체적 사례 표기 & 기하 정돈 (Concrete Values & Clean Geometry Gate)
- [ ] `"이름 A"`, `"대상 X"` 같은 추상 임시 토큰 대신 `"장안산"`, `"5.10 설악 트레일 50K"`, `"① 달러 표시 새 계약"`, `"1곳 입찰"` 같은 실제 사례나 구체적 값을 적었는가?
- [ ] 맥락 없는 기괴한 추상 아이콘이나 여러 박스를 어지럽게 가로지르는 스파게티 곡선이 없는가? (단, 지도의 실제 코스 곡선, 등고선, 고도 단면도처럼 대상 자체를 묘사하는 곡선·다각형은 적극 허용한다.)
- [ ] 3열 이상의 다차원 텍스트 비교는 억지로 SVG로 그리지 않고 HTML `<table>`로 처리했는가?

## 4. 텍스트·도형 충돌 0건 (Zero-Collision Gate)
- [ ] 글자와 글자, 글자와 박스 테두리, 글자와 연결선이 단 1px도 겹치거나 잘리지 않는가?
- [ ] 화살표나 선 위에 글자가 얹혀 가독성을 해치는 곳이 없는가?

## 5. 의미 색상 일치 & 빨강 절제 (Semantic Color & Restraint Gate)
- [ ] 결론 내용이 **"위법 / 성립 불가 / 삭제됨 / 기준 미달 / 허용 불가"**일 때, 그것이 올바른 판정(정답)이라는 이유로 초록색으로 칠하지 않고 **빨간색(`#b3352b`) 또는 중립 먹색**으로 칠했는가?
- [ ] 빨간색을 선·아이콘·배지·테두리 사방에 난무시키지 않고 **실제 결함 핵심 1~2곳에만 절제**해 시선이 꽂히게 했는가?

## 6. 자연스러운 읽기 흐름 (Context → Visual → Detail Flow Gate)
- [ ] 각 도식 앞뒤로 **[짧은 맥락 도입 문단 `<p>`] → [시각 도식 `<figure>`] → [한 줄 핵심 캡션 `<figcaption>` 또는 상세 불릿]**의 자연스러운 읽기 흐름이 갖추어져 있는가?

## 7. 본문-도식 간 중복 방지 (Anti-Redundancy Gate)
- [ ] 같은 섹션 안에서 SVG 도식과 아래 HTML 표/카드가 똑같은 단어를 그대로 두 번 반복하지 않고, 도식은 시각적 장면·구조를, 본문/표는 상세 조건이나 판정 근거를 분담하고 있는가?

## 8. 독자 반문 테스트 (Cold-Reader "So What?" Gate)
완성된 `[도입 문단 + SVG 도식 + 캡션]` 세트를 배경을 모르는 독자 눈으로 읽었을 때 아래 반문이 하나라도 떠오르면 불합격으로 보고 즉시 보완한다:
- [ ] **"그래서 그게 지금 오답·보류랑 무슨 상관인데?"** — 중간 인과 고리가 생략되지 않았는가?
- [ ] **"저 전제·예외 규칙이 도대체 뭔데, 있으면 뭐가 달라져?"** — 배경 지식 없는 독자에게 전제("차량임차는 임대차로 보아", "특정 예외 의무 규칙" 등)를 설명 없이 던지지 않았는가?
- [ ] **"원래 저 장치는 왜 있고, 정확히 뭐가 잘못됐다는 거야?"** — 정상 의도와 오발 지점이 분명히 대비되는가?
- [ ] **"이 단어·번호(`q029` 등)가 대체 무슨 뜻이야?"** — 처음 보는 독자가 모를 내부 용어·시험 번호·코드 식별자를 번역 없이 던지지 않았는가?

## 9. 목적형 모션·인터랙션 검수 (모션/인터랙티브 적용 시)
- [ ] **Static-First**: 아무것도 클릭하지 않은 초기 화면에서도 전체 구조와 핵심 결론이 온전히 읽히는가?
- [ ] **실제 SVG 내부 변화**: CSS 텍스트 박스 하이라이트로 때우지 않고, `<svg>` 내부의 경로·노드·탈락 표시(`✕`·흐림)·수치 상태가 실제로 움직이거나 전환되는가?
- [ ] **접근성·조작성**: `@media (prefers-reduced-motion: reduce)`가 적용되었고, 시나리오 전환 또는 단계 재생(이전/다음/초기화)이 `<svg>`를 가리지 않는 상단 `.controls` 바에 배치되었는가?
