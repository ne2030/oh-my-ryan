# Visual Explainer 핵심 방법론 (Layered Core)

시각화의 목적은 **본문 텍스트를 네모 박스 몇 개에 나눠 담는 것(`□ → □ → □`)이 아니라, 글만으로는 한눈에 파악하기 어려운 실제 장면·구조·데이터의 작동과 원인을 직관적인 시각 구조로 조립해 단박에 이해시키는 것**이다.

---

## 0. 그리기 전 확인 & 독자 납득 3원칙 (공통)

도형을 배치하기 전에, 목적과 독자 맥락이 분명한지 먼저 확인한다.

- **조건부 1턴 짧은 인터뷰 (불분명할 때만)**:
  - 시각화의 목적(원인 해부 vs 아키텍처·프로세스 소개 vs 수치·옵션 비교), 읽을 독자, 원하는 톤·팔레트가 모호할 때만 그리기 전에 **1~2문항으로 짧게 묻고** 시작한다.
  - 문서 맥락이나 요청에서 목적과 톤이 이미 분명하다면 굳이 묻지 않고 바로 진행한다.

그다음 배경 지식이 없는 독자 머릿속에서 설명이 끊기지 않고 이어지는지 확인한다:

1. **중간 인과·전제 생략 금지**: *"A가 없다 / 다르다"*에서 끊지 말고, **왜 그 조건·규칙이 필요한지, 그것이 있었으면 어떻게 되고 없어서 지금 어떤 결과가 나오는지** 도입 문단과 도식이 이어지게 드러낸다.
2. **배경 없는 전문 용어·내부 식별자 번역**: 내부 테스트 번호, 코드 변수명, 줄 번호, 약어만 불쑥 던지지 않고 **구체적인 실제 사례 이름과 역할이 바로 드러나는 말**로 먼저 풀어 쓴다.
3. **구체적 사례 우선**: `"이름 A"`, `"항목 1"`, `"단계 1"` 같은 추상 토큰 대신 독자가 머릿속에 즉시 그릴 수 있는 실제 값·사례·사물 이름을 적는다.

---

## 1. 1장면 콘티(`<desc>`) 우선 설계 (공통)

도형을 그리기 전에 `<svg>` 안의 `<desc>` 태그에 **독자가 단박에 깨달아야 할 '단 하나의 핵심 장면·대비'**를 자연어 1~2문장으로 먼저 쓴다.

- **금지 (부품 배치 명세서)**: *"위에는 초록 체크 카드, 아래엔 찢긴 점선 표, 그 아래 원형 점 10개, 가운데 수직 게이트, 아래쪽 개선 트랙..."*처럼 도형 부품과 색을 나열하며 한 캔버스에 억지로 욱여넣는 콘티.
- **필수 (1장면 지문)**: *"4개 필드 중 위 3개는 일치하는데 맨 아래 문장만 따옴표 1글자가 달라 새 항목으로 오인돼 필터에서 삭제된다"*처럼 **핵심 사건과 대비 1개**만 선명하게 서술한다.

## 1-B. 주제 유형별 적용 규칙 (해당 경우에만 선택 적용)

모든 도식에 같은 틀을 강제하지 않고, 설명하려는 주제의 성격에 맞는 규칙을 적용한다.

### 유형 A. 오류·결함·원인 해부 ("왜 깨졌는가?")
- **문제와 해결 분리**: 원인 도식은 **“지금 어디서, 왜 깨졌는가”에만 100% 집중**한다. 한 그림에 `현재 고장`과 `고친 뒤 / 목표 화면`을 Y자로 억지로 합치지 않는다(해결안은 별도 탭·별도 도식으로 분리). 단, 현재 왜 틀렸는지 판별하기 위해 필수인 **정상 기준선(한도선·정상 작동 기준)**만 함께 둘 수 있다.
- **다중 원인 분해**: 핵심 원인이 2개 이상이면 1개 SVG에 구겨 넣지 않고 **`[간단한 전체 현상 1개] + [원인별 독립 도식]`**으로 분해한다.
- **원래 의도 vs 오발 대비**: 필터·검사·규칙이 문제를 일으킨 경우, 원래 걸러내려던 대상(정상 의도)과 잘못 걸려든 대상(오발)을 대비한다.
- **상태 요약 카드 도피 금지**: 원리·원인을 설명해야 하는 자리에 “구현 완료 / 기준 미정 / 남은 조치 체크리스트” 같은 프로젝트 진행 현황표로 때우지 않는다.

### 유형 B. 시스템·아키텍처·현장 프로세스 ("어떻게 동작하는가?")
- **추상 단계 박스 일렬 나열(`A → B → C → D`) 금지**: 본문 불릿에 적힌 개념 이름표만 네모 4개에 옮겨 적지 않는다.
- **실제 사례 1건의 변환·분기·계층 호출로 표현**:
  - 소프트웨어/데이터 시스템이라면 **실제 입력 1건이 어떤 슬롯으로 변환되고, 어떤 규칙 트리·분기·하위 계층을 거쳐 최종 결과로 합류하는지**를 그린다.
  - DB/인프라 전환이라면 단순 화살표 대신 **실제 계층 스택, Blue/Green 스왑 스위치, 경계선** 등 구조적 메커니즘을 직접 그린다.
- **물리 현장·사람 작업 흐름은 실제 사물·공간 장면으로 재현**:
  - 공장·물류·오프라인 현장이나 UI 여정이라면 네모 박스 대신 **실제 사물(포스트잇, 라벨 프린터, 종이 더미, 작업대 위 A4 배치, 3D 상자), 작업자(사람), 얽힌 다중 공정 경로 망**을 간결한 벡터 일러스트로 그려 글 안 읽어도 장면이 보이게 한다.

### 유형 C. 수치·비율·임계값·집합 비교
- 상자 안에 문장으로 설명하지 않고 **기준선(`line`)을 가로지르는 범위·임계값 막대**, **100% 누적 비율 막대**, **점 격자(`●/○`)**, **중첩·포함 경계 영역**으로 위치와 길이 자체가 메시지를 말하게 한다.
- 3열 이상의 다차원 텍스트·옵션 비교는 억지로 SVG로 그리지 않고 시맨틱 HTML `<table>`로 분리한다.

## 2. 글(HTML)과 그림(SVG)의 역할 분담

- **이야기와 인과 서술은 HTML 본문(`<p>`, `<figcaption>`)이 담당한다.** 화면에 `"독자 질문:"`, `"Q:"` 같은 메타 라벨을 출력하지 않는다.
- **SVG 내부 텍스트는 짧은 명사구·실제 값·기호만 사용한다**: 2~14자 내외의 짧은 라벨, 실제 값, 상태 기호(`✓`, `✕`, `?`)만 두고, 한 요소 안 텍스트는 최대 2줄을 넘기지 않는다.
- **중복 텍스트 제거**: 화살표나 하위 영역이 이미 보여주는 분기/역할을 위쪽 박스 안에 문장으로 중복해서 적지 않는다.

---

## 3. 장식용 래퍼 중첩 금지 & 정돈된 기하

- 글자 박스를 묶기 위한 무의미한 다중 외곽 테두리(Wrapper Box-in-Box)는 쓰지 않는다.
- 반면 장면 캔버스, 미니 화면 프레임, 데이터 레코드 슬롯, 작업대 평면도, 규칙 트리, 포함 경계처럼 **실제 대상을 묘사하는 내부 구성요소**는 적극 활용한다.
- 박스를 피하려다 맥락 없는 잡다한 장식 기호를 남발하지 않는다.

---

## 4. 색상·타이포그래피: 검증된 디폴트 + 맥락에 맞는 자유 변주

- **디폴트 퀄리티 보장 (`read-patterns.mjs`)**: 별도 브랜드·문서 스타일이 없으면 `scripts/read-patterns.mjs`의 기본 에디토리얼 팔레트(흰 바탕 `#ffffff`, 먹색 `#37352f`, 회색 `#6b6862`, 파랑 `#2f6ba3`, 초록 `#2f6f4d`, 빨강 `#b3352b`, 황토 `#8a5a18`)와 가독성 높은 산세리프 타이포를 디폴트로 써서 안정적인 완성도를 확보한다.
- **맥락·브랜드에 맞는 다양화 허용**: 이 색상과 폰트에 갇히지 않는다. 기존 문서·포트폴리오·제품의 고유 팔레트(예: 딥틸+테라코타, 모노크롬 에디토리얼, 다크 모드, 브랜드 서체 등)가 있거나 사용자가 다른 분위기를 원하면 그 톤에 맞춰 자유롭게 변주한다.
- **변주해도 지킬 2가지 불변식**:
  1. **강조색 절제 (최대 3~4색 + 중립 회색)**: 특히 경고·결함 색(빨강 등)은 **실제로 깨지거나 강조할 핵심 1~2곳**에만 집중해 쓰고 사방에 난무시키지 않는다.
  2. **의미 일치**: 결론이 부정적(위법·초과·삭제·실패)이라면 정답이더라도 긍정 색(초록 등)으로 칠하지 않는다.

---

## 5. 레이아웃 불변식 (충돌 0건 & 가독성)

- **충돌 0건**: 어떤 `<text>`도 다른 `<text>`, 테두리, 화살표 선과 1px도 겹치면 안 된다.
- **크기와 여백**: `viewBox` 폭은 본문 폭(`720~960`)에 맞춰 `1:1` 스케일로 잡고, 주요 라벨은 읽기 쉬운 크기(`12~16px`)와 넉넉한 여백을 확보한다.
- **공용 템플릿 대량 찍어내기 금지**: 여러 항목을 그릴 때 공용 박스 생성기로 찍어내지 않고 각 항목의 구조에 맞게 개별 설계한다.

---

## 6. 목적형 인터랙션·모션 (요청 시 Static-First)

- 클릭·재생 전 **초기 정지 프레임만 봐도 전체 구조와 핵심 대비가 100% 읽혀야 한다.**
- 컨트롤(`.controls`)은 `<svg>` 위쪽에 배치하고, `@media (prefers-reduced-motion: reduce)`를 준수한다.
