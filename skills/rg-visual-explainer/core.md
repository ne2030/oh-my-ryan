# Visual Explainer 핵심 방법론 (v1.2.0)

시각화의 목적은 **"본문 텍스트를 네모 박스 안에 다시 적거나 정해진 차트 템플릿에 끼워 맞추는 것"이 아니라, 독자가 글만으로는 한눈에 파악하기 어려운 실제 장면·화면·데이터의 작동과 원인을 직관적인 시각 구조로 조립해 단박에 이해시키는 것**이다.

---

## 0. 그리기 전 인과 완결 4원칙 (독자 납득 기준)

시각 배치를 짜기 전에, 설명의 논리 자체가 **배경 지식이 없는 독자** 머릿속에서 끊기지 않고 이어지는지 먼저 확인한다.

1. **중간 인과 고리 생략 금지**: *"A가 없다 / 다르다"*에서 끊지 말고, **`[A가 있었으면 → B가 추론·작동해 맞았을 텐데] → [A가 없어서/어긋나서 → C(오답·보류)가 됐다]`**까지 본문과 도식이 이어지게 드러낸다.
2. **배경 없는 전제·점프 금지**: *"차량임차는 임대차로 보아"*, *"특정 예외 의무 규칙을 조회하지 못해"*처럼 배경 지식이 없으면 이해할 수 없는 전제를 불쑥 던지지 않는다. **왜 그 쟁점이 생기는지, 그 규칙이 조회됐으면 결론이 어떻게 달라지는지, 가능한 결과 타입들이 무엇인지**를 도입 문단에서 먼저 1~2문장으로 풀어 준다.
3. **원래 의도 vs 오발 대비**: 필터·검사·규칙이 문제를 일으킨 경우, **"원래 걸러내려던 대상(정상 의도)"**과 **"잘못 걸려든 대상(오발)"**을 나란히 대비해 장치 자체가 버그인지 적용 범위가 삐끗한 건지 헷갈리지 않게 한다.
4. **내부 용어·시험 번호 번역**: 시스템 내부 명칭, 코드 변수명, 줄 번호, **`q001`·`q029` 같은 내부 시험 번호**를 본문 첫 문장이나 SVG 라벨에 그대로 던지지 않고 **실제 사례 이름과 역할이 바로 드러나는 쉬운 말**(예: "차량임차 5,700만원 계약", "재공고 소액수의 지역제한")로 쓴다.

## 1. '1장면 콘티(`<desc>`)' · 문제/해결 분리 · 다중 원인 분해

도형을 그리기 전에 "어떤 부품을 넣을까?"부터 생각하지 않는다. 먼저 `<svg>` 안의 `<desc>` 태그에 **독자가 단박에 깨달아야 할 '단 하나의 사건·어긋남 장면'**을 자연어 1~2문장으로 적는다.

1. **콘티(`<desc>`)는 '도형 부품 배치 명세서'가 아니라 '한 장면 지문'으로 쓴다**:
   - **금지**: *"위에는 초록 체크 카드, 아래엔 찢긴 점선 테두리 표, 그 아래엔 원형 점 10개 막대, 가운데 수직 게이트, 아래쪽 개선 트랙..."*처럼 **도형 부품·색·테두리를 나열하며 한 캔버스에 억지로 욱여넣는 콘티**.
   - **필수**: *"4개 칸 중 위 3개는 일치하는데 맨 아래 설명 문장만 따옴표 1글자가 달라 '새 사실'로 오인돼 삭제 필터로 넘어간다"*처럼 **독자가 이해해야 할 단 하나의 핵심 사건과 대비**를 먼저 쓴다.
2. **문제와 해결을 한 그림에 Y자로 섞지 않는다 (문제 초점 집중)**:
   - 원리·원인을 설명하는 도식은 **“지금 어디서, 왜 깨졌는가”에만 100% 집중**한다.
   - 하나의 입력에서 위(`현재 고장`)·아래(`게이트 적용 시 / 목표 화면 / 고친 뒤`)를 Y자로 한 그림에 억지로 합치면, 독자가 **“이게 지금 문제 상황인지 해결안인지”** 헷갈리고 시선이 분산된다. 해결안은 별도 탭이나 별도 해결 도식으로 분리한다.
   - 단, **정상 기준선**(예: `한도 2,000만원`, `2인 이상 성립`)이나 **원래 정상 작동 대비**처럼 *“지금 왜 틀렸는지”*를 판별하기 위해 필수인 기준만 함께 둔다.
3. **원인이 2개 이상이면 한 그림에 구겨 넣지 않고 `[간단한 전체 현상 1개] + [원인별 독립 도식]`으로 분해한다**:
   - 서로 다른 원인 2~3개가 겹친 이슈를 1개 SVG에 다 우겨 넣으면 구조가 복잡해지고 각 원인의 메커니즘이 흐려진다.
   - 반드시 **① 전체 현상 요약 도식 1개**(무엇이 어떻게 막혔는지 단순하게) + **② 원인 1 · 원인 2 각각의 핵심 메커니즘을 해부하는 독립 도식들**로 나누어 그린다.
4. **추상 이름표 대신 '실제 벌어지는 장면·화면·데이터'를 직접 그린다**:
   - **시각·공간 장면 재현 (Scene Simulation)**: 캔버스를 실제 장면(뷰포트)으로 삼아 지형 능선, 경로 곡선, 등고선, 시야각 등을 직접 그려 공간상의 차이를 눈으로 보게 한다.
   - **미니 화면 와이어프레임 (Mini-UI Sketch)**: 빈 이름표 박스 대신 실제 화면 프레임 안의 필터 바, 목록 행, 미니 곡선·데이터 항목을 스케치한다.
   - **데이터·문서 슬롯과 기하 대비**: 실제 레코드의 필드 슬롯 변화, 기준선을 가로지르는 범위·임계값 막대, 100% 누적 비율 막대, 점 격자(`●/○`) 등으로 **도형의 위치·길이·빈 구멍·단절 자체가 의미를 말하게** 한다.
5. **원리·원인을 상태 요약 HTML 카드로 도망치지 않는다**:
   - 원인↔조치 매핑이나 단순 목록 비교는 HTML 표로 처리할 수 있지만, **원리와 원인을 설명해야 하는 자리에 “구현 완료 / 기준 미정 / 남은 조치 체크리스트” 같은 프로젝트 진행 현황 HTML 카드로 때우는 것은 금지**한다.
6. **공용 템플릿 대량 찍어내기 금지**:
   - 여러 항목을 시각화할 때 공용 박스·카드 생성 함수나 고정 템플릿으로 압축해 찍어내지 않고, 각 항목의 실제 원인과 구조에 맞춰 개별 설계한다.

## 2. 글(HTML)과 그림(SVG)의 엄격한 역할 분담

SVG는 **기하학적 관계와 시각적 대비**를 보여주는 공간이지, 문장을 읽는 공간이 아니다.

- **이야기와 문장 설명은 HTML 본문(`<p>`, `<figcaption>`)이 담당한다**:
  - 왜 이 동작이 일어났는지, 배경 맥락과 인과 서술은 반드시 도식 위아래의 HTML 문단과 캡션에 적는다.
  - 화면에 노출되는 설명에 `"독자 질문:"`, `"이 도식이 답하는 질문:"`, `"Q:"` 같은 메타 라벨을 출력하지 않는다.
- **SVG 내부 텍스트는 '짧은 명사구·실제 값·기호'로만 제한한다**:
  - SVG 안의 텍스트는 **2~14자 내외의 짧은 명사구, 실제 사례 이름, 필드명, 수치, 상태 기호(`✓`, `✕`, `?`)**만 사용한다.
  - `"~하기 때문에 ~가 발생한다"` 같은 서술형 문장이나 긴 줄글을 SVG `<text>`로 넣지 않는다.
  - 한 요소 안의 텍스트는 최대 **2줄(제목 1줄 + 짧은 보조 값 1줄)**을 넘기지 않는다.

## 3. 장식용 래퍼 박스 중첩 금지 vs 구체적 내부 묘사(장면·미니 화면·슬롯) 허용

1. **무의미한 장식용 외곽 박스 중첩 금지**:
   - 글자 박스를 묶겠다는 이유로 아무 시각적 정보가 없는 바깥 컨테이너 박스 안에 서브 박스를 넣고 그 안에 또 아이템 박스를 넣는 **장식용 다중 테두리(Wrapper Box-in-Box)**는 절대 쓰지 않는다. 그룹 구분은 여백, 정렬, 얇은 구분선(`line`), 혹은 중괄호로 충분하다.
2. **구체적 장면·미니 화면·데이터 슬롯의 내부 묘사는 적극 허용**:
   - 장식용 테두리와 달리, **실제 대상을 묘사하기 위한 내부 구성요소**는 자유롭게 그린다:
     - **장면 캔버스(Viewport)** 안에 그려진 지형 폴리곤, 등고선, 경로 곡선, 러너, 카메라 시야각
     - **미니 화면 프레임(Mini-UI)** 안에 그려진 검색 필터 바, 리스트 행, 미니 코스 지도, 미니 고도 그래프, 채워진 카드 필드
     - **데이터 레코드/문서** 안에 나란히 놓인 실제 필드 슬롯이나, **포함/교집합 범위 영역** 안에 찍힌 사례 점(`●`)
3. **추상 플레이스홀더 금지 & 정돈된 기하 표현**:
   - `"이름 A"`, `"대상 X"`, `"항목 1"` 같은 추상 임시 토큰 대신 **`"장안산"`, `"5.10 설악 트레일 50K"`, `"① 달러 표시 새 계약"`, `"1곳 입찰"`, `"추정가격 3,273만원"`**처럼 독자가 즉시 이해할 수 있는 구체적 사례나 실제 값을 적는다.
   - 출처 불명의 추상 아이콘(기괴한 퍼즐 조각, 정체불명의 스패너 등)이나 여러 도형을 어지럽게 가로지르는 스파게티 곡선은 쓰지 않는다. (단, 지도의 실제 코스 곡선, 등고선, 고도 단면도처럼 **대상 자체의 모양인 곡선·다각형**은 적극 사용한다.)
   - 3열 이상의 텍스트·판정 비교는 SVG로 그리지 말고 시맨틱 HTML `<table>`로 분리한다.

## 4. 색상의 절제와 의미 일치 (최대 3~4색 + 중립 회색)

1. **색상 수 제한과 의미 고정**:
   - 기본 배경은 흰색(`#ffffff`) 또는 장면 캔버스용 옅은 지형/화면 톤(`#f3efe6`, `#f7f8fa` 등)을 쓰고, 중립 요소는 회색/먹색(`#37352f`, `#6b6862`, `#d3d1cb`)으로 그린다.
   - 의미 색상은 다음 3~4가지로 엄격히 절제한다:
     - **손실 / 위반 / 기준 미달 / 금지 / 한도 초과 (Red)**: 텍스트·선 `#b3352b`, 채움 `#fdf2f1`
     - **정상 유지 / 성립 / 충족 / 허용 (Green)**: 텍스트·선 `#2f6f4d`, 채움 `#eef6f1`
     - **핵심 제어 / 새 기준 / 장면 포커스 (Blue / Orange)**: 텍스트·선 `#2f6ba3` (채움 `#f3f7fb`), 혹은 지도 경로 포커스 `#f97316`
     - **주의 / 미확정 / 일부 구현 (Amber)**: 텍스트·선 `#8a5a18`, 채움 `#fdf8ee`
2. **내용의 의미와 색상 일치 + 빨간색 절제 (평가 상태와 혼동 금지)**:
   - 결론 내용이 **"위법 / 성립 불가 / 기각 / 삭제됨 / 허용 불가"**라면, 그것이 올바른 판정(정답)이더라도 **초록색으로 칠하지 않고 빨간색(`#b3352b`) 또는 중립 먹색**으로 표시한다.
   - **빨간색 남발 금지**: 빨간색은 실제로 깨지거나 누락된 **핵심 결함 지점 1~2곳**에만 집중해 쓰고, 선·아이콘·배지·테두리 사방에 빨강을 칠해 시선을 분산시키지 않는다. 보조 요소와 중립 흐름은 회색/먹색(`#37352f`, `#6b6862`, `#d3d1cb`)으로 낮춘다.

## 5. 레이아웃 불변식 (충돌 0건 & 여백 확보)

- **텍스트·선 충돌 0건**: 어떤 `<text>`도 다른 `<text>`나 도형 테두리, 화살표 선과 겹치면 안 된다. 화살표나 연결선 위에는 라벨을 얹지 말고 빈 공간에 배치한다.
- **타이포그래피와 크기**:
  - SVG `viewBox` 폭은 본문 폭(`720~960`)에 맞춰 `1:1` 스케일로 잡고, 캔버스를 억지로 축소해 글씨가 작아지게 만들지 않는다.
  - SVG 내부 주요 라벨은 `14~16px` (`font-weight: 600~700`), 보조 값/축 눈금은 `12.5~14px` 이상으로 설정한다.
- **충분한 호흡**: 한 도식의 세로 높이는 필요한 만큼 여유 있게(`180~460px`) 잡고, 요소 간 간격과 캔버스 여백을 넉넉히 두어 답답하지 않게 한다.

## 6. 목적형 인터랙션·모션 그래픽 (Static-First Motion)

사용자가 모션그래픽·애니메이션·인터랙티브 설명을 요청했거나, **시간 흐름·탐색 경로·레이어 가림·자원 포화·What-if 조건 비교**처럼 움직임이 이해도를 크게 끌어올리는 주제에는 정적 SVG 위에 **목적형 모션·인터랙션**을 결합한다.

1. **Static-First 불변식**: 클릭하거나 재생하기 전 **초기 정지 프레임만 봐도 전체 구조와 핵심 대비가 100% 읽혀야 한다.** 빈 캔버스나 클릭해야 글자가 나타나는 숨김형 UI를 만들지 않는다.
2. **이해도를 높이는 4가지 모션·인터랙션 패턴**:
   - **경로 추적·단계 재생 (Step/Traversal Motion)**: 탐색·파이프라인·상태 전이에서 활성 경로를 `stroke-dashoffset` 흐름이나 단계 하이라이트로 따라가며, **탈락·스킵된 분기·블록은 명확히 흐려지고(`opacity`) 빨간 점선·`✕`로 배제**되게 보여 준다. (재생/일시정지·이전/다음·초기화 컨트롤 제공)
   - **시나리오·What-if 전환 (Scenario Switch)**: 같은 자료구조·시스템에 다른 입력(예: `단건 조회(=)` vs `범위 조회(BETWEEN)`, `정렬 적재` vs `무작위 섞임`)을 걸었을 때 **어디서 성공하고 어디서 망가지는지** 같은 SVG 캔버스 안에서 즉시 대조한다.
   - **커튼 비교·레이어 토글 (Curtain / Layer Compare)**: 가림 현상·Before/After 시각 차이를 슬라이더(`clipPath`)나 토글 버튼으로 직접 밀어 비교한다.
   - **순수 CSS 미세 방향성 (Subtle Flow)**: 데이터 흐름·루프 방향에 느린 점선 흐름(`stroke-dashoffset`)이나 대상 점의 미세 맥동(`pulse`)을 절제해 사용한다.
3. **제어 바와 접근성**:
   - 컨트롤(`.controls`: 시나리오 버튼, 재생/단계 버튼, 슬라이더, 상태 배지)은 `<figure>` 안의 `<svg>` 위쪽에 깔끔하게 배치해 도식 내부를 가리지 않는다.
   - 모든 CSS 애니메이션은 `@media (prefers-reduced-motion: reduce)`에서 정지되도록 처리한다.
   - CSS `<div>`/`<span>` 텍스트 박스에 하이라이트만 옮기는 가짜 인터랙션은 금지한다. 모든 모션·상태 변화는 **실제 구조가 그려진 `<svg>` 내부 요소**에 적용한다.
