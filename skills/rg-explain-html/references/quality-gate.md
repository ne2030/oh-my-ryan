# 설명 HTML 독립 검수 기준 (Quality Gate)

HTML 초안을 완성한 뒤 사용자에게 내보내기 전에 아래 7개 기준으로 점검한다. **하나라도 걸리면 `revision-required`로 판정하고 해당 절을 고친 뒤 다시 확인한다.**

## 1. 도메인 배경·맥락 선행 (처음 보는 사람이 무슨 이야기인지 아는가?)
- 도입부에서 **"이 문서가 어느 시스템·무슨 업무(도메인)에 관한 이야기인지"** 전체 맥락을 먼저 설명했는가?
- 각 절의 첫 문단이 배경 설명 없이 수치·기호부터 던지지 않고, **원래 업무·시스템이 어떻게 동작하는지**를 먼저 설명한 뒤 사례로 들어가는가?
- 제목과 핵심 명제가 특정 사례 하나로 좁혀지지 않고 일반 원리를 말하며, 사례는 예시로 구분되어 있는가?
- 문제·개선 절에서 **사례가 해결책 쪽에만 등장하지 않고**, 같은 사례 하나가 **문제 발생(Before) → 원인 → 해결 후 결과(After) → 대안 비교**까지 관통해 전후 비교가 되는가?
- 도식을 넣었다는 이유로 본문 설명(`p`)을 2~3문장으로 축약해 버리지 않았는가? (절당 배경·핵심 논리·대안 또는 경계가 온전히 읽힐 분량이어야 한다.)
- 미확정 사항이 있을 때, 누가 무엇을 정해야 다음으로 넘어가는지 분명한가?

## 2. 기호·약어 자명성
- 본문과 도식 라벨에 나오는 모든 기호·약어(`A`, `B`, `K` 등)가 첫 등장 자리에서 정체와 역할을 밝힌 뒤 쓰였는가?

## 3. 긍정형 서술 · 방어적 면책 문구(Disclaimer) 제로
- 긍정형 원칙과 예외를 지켰는가? (꼭 지켜야 할 경계, 명시적 제한, 생략 시 오해 방지처럼 강한 이유가 있는 부정문은 유지하되, **독자가 가정하지 않은 전제를 반박하지 않는다.**)
- 아래 방어적 면책 문구가 본문·각주·캡션 어디에도 없는가?
  - *"~라는 사실만으로 ~가 확정/완료되는 것은 아니다"*
  - *"~의 다른 조건까지 대신 판단하지는 않는다"* / *"~에 따라 달라진다"*
  - *"이 문서는 구체적인 결론/수치를 정하지 않는다"*
  - *"설명을 위한 가상 사례일 뿐이다"*
- 확정된 적용 제외·증거 한계·관측과 가정의 구분은 필요한 경계로 직접 적고, 미확정 사항은 무엇이 비어 있고 누가 확정해야 하는지 밝혔는가?

## 4. 진짜 시각화 (`rg-visual-explainer` 8항목 검수 연동)
- `../rg-visual-explainer/references/visual-gate.md`의 8항목(시각 콘티 `<desc>`, SVG 문장·래퍼 박스 금지, 구체적 사례·기하 정돈, 충돌 0건, 의미 색상 일치, 읽기 흐름, 중복 방지, 독자 반문 테스트)을 모두 통과했는가?
- **인라인 `<svg>` 필수 · CSS 박스+`→` 대용 금지**: 구조·메커니즘·비교 설명 절에 실제 인라인 `<svg>`가 있는가? CSS `<div>`/`<span>` 테두리 박스를 flexbox로 늘어놓고 텍스트 `→`로 이어서 도식을 대신하지 않았는가?
- **자동 하드 게이트 통과**: `node <skill-root>/scripts/check-html.mjs <생성된_HTML_경로>` 실행 결과가 `FAIL` 0건인가?
- 도식 안의 문장을 가리고 **도형·선·위치·기준선·색만 남겼을 때도** 핵심 구조(수치 경계, 포함/계층, 허용 vs 차단, 분기)가 읽히는가?
- **표 남용·도입부 SVG 1개 쏠림 금지**: 도입부에만 SVG 1개가 있고 본문 핵심 절(작동 방식 비교, 사례별 분기, 선택 기준 등)이 연속으로 `<table>`로만 채워져 있지 않은가? (`<table>` 수가 `<svg>` 수보다 월등히 많거나, 표 셀 안에 2문장 이상의 인과·배경 설명이 들어갔다면 도식으로 분리해야 할 신호다.)
- 문제·오판·경계가 있는 주제라면, 단순히 입력 숫자만 찍어두지 않고 **기존 방식의 오판 지점**이나 **차단 경로(점선·✕)**가 함께 보이는가?

## 5. 도식과 본문의 역할 분담
- 도식에 이미 그린 노드 이름을 바로 아래 2열 카드나 목록으로 말만 바꿔 되풀이하지 않았는가?
- 반대로, 도식만 덩그러니 두고 주제에 필요한 역할·동작·근거(문제·개선이면 원인·해결 이유) 설명을 통째로 생략하지는 않았는가?

## 6. 흐름 연결·스캔 가독성
- **흐름과 위계**: 목차만 읽어도 문서의 큰 그림과 순서가 이해되는가? 전체 안내는 도입 다음, 세부보다 앞에 있어 여러 절을 다 읽고 조립할 필요가 없는가? 절과 절·문단과 문단이 독립 토막처럼 끊기지 않고 자연스럽게 이어지는가?
- **스캔 구조화**: 도식 아래의 본문 텍스트가 소제목(`h3`)·역할 라벨 없이 민무늬 `<p>` 문단만 줄줄이 이어지거나, 반대로 똑같은 색·무게의 소제목 5~6개만 수직으로 단조롭게 나열돼 있지 않은가? (`Before vs After`·`문제·원인 vs 해결`은 2열 대비와 의미 색으로 시각 구분이 되어야 한다.)
- **사례-그림 일치**: 대표 사례를 본문과 그림에서 각각 따라갔을 때 같은 입력이 같은 조건을 거쳐 같은 결과에 도달하는가?
- **첫 화면·혼합 금지**: 첫 화면에 그림·표·구조 개요 없이 문단만 보이지는 않는가? 서로 다른 질문의 답을 한 문단이나 긴 표 셀·카드에 섞어 독자가 스스로 분류하게 만들지 않았는가?
- **안티패턴 금지**: 좌측 컬러 띠 카드(`border-left` 액센트), 5개 이상 평면 불릿, 10개 이상 동종 카드 그리드 도배가 없는가? 화면에서 3줄을 넘는 문단(본문 `<p>` 및 표·카드·목록 셀 모두)이 없는가?
- **탐색 장치**: 섹션 6개 이상 또는 주요 시각 블록 8개 이상인 긴 문서에 좌측 고정 사이드바 목차가 있는가? (단, 섹션 내부에 또 세로 좌측 탭을 중첩하지 않았는가?)

## 7. 내용 정확성과 화면·보고 확인
- **근거·반례·다양성**: 검증 책임·시험 조건·채택/실패·기존 차단 조건이 있는 주제는 본문 위치와 실제로 대조했는가? 참조 자료가 없다는 이유로 기존 조건을 완화하지 않았으며, 유지한 조건과 확인하지 못한 근거를 구분했는가? 새로 넣은 설명마다 반례를 따져 보았고, 예시가 여러 경우를 고르게 보이는가?
- **허수아비 대안 금지 & 대안 비교 구조**: 명백히 열등하거나 기존 버그에 불과한 방식을 억지로 "대안"으로 세워 비교하지 않았는가? 실질적 대안이 있을 때, 줄글 한 문단에 뭉개지 않고 **비교 표(`방식 | 장점 | 한계·부담`)**나 같은 축의 비교 블록으로 제시했는가? (없으면 생략)
- **개선 기록**: 기존 문서를 개선한 경우 삭제·이동·대체한 핵심 설명의 새 위치·역할·바꾼 이유를 작성·검토 기록에 남겼는가?
- **화면 확인**: 브라우저 실행이 가능한 환경에서 렌더 스크린샷으로 첫 화면과 각 절의 정보 관계·넘침·도식 글자 크기를 확인했는가? (불가능한 환경이면 하지 못한 검증으로 보고한다.)
- **자체 비평 보고**: 확인한 스크린샷(가능 환경)과 자체 비평(잘된 점, 남은 문제와 원인, 새로 넣은 해석, 하지 않은 검증)을 함께 보고할 준비가 되었는가?
