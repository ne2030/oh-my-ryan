작업 준비 단계에서 의도와 계약의 원문을 전달한다

에이전트가 작업의 의도나 기존 계약을 놓친 사례가 있다. 관련 문서가 저장소에 있는데도 실제 작업 입력에는 빠지고, 경로·절 힌트만 전달된 채 본문 읽기로 이어지지 않는 단절이 확인됐다. 이 제안은 이미 있는 원문 읽기 기능을 작업 준비 경로 안에서 수행하게 하고, 그 결과에 의미 본문을 담아 작성·구현·검토 입력으로 넘긴다.

확인된 문제와 이번 해결 범위

관찰된 것은 두 가지다. 문맥 조회 경로는 작업이 직접 지정한 입력, 상위 범위가 물려주는 문맥, 제한된 들어오는 관계만 모으고 본문은 돌려주지 않는다. 그리고 같은 작업이라도 어느 진입점으로 들어오느냐에 따라 보는 근거가 달라진다 — 문서 작성 직전 경로는 상위 의도와 제품 정의를 더 얹고, 독립 구현 검토 경로는 작업이 직접 선언한 필수 입력만 쓴다.

이 제안은 그 단절만 다룬다. 문서를 열지 않은 것이 모든 의도 실패의 원인이라고 단정하지 않는다. 문서를 읽은 뒤에도 기존 정책을 결과에 쓰지 않은 사례가 따로 있고, 그것은 원문 전달로 해결되지 않는다.

세션 시작 안내가 경로와 절 힌트만 제한된 개수·길이로 주고 본문을 주지 않는 것, 작업이 여럿이면 목록과 재조회를 안내하는 것은 의도된 경량 진입 계약이며 결함이 아니다. 이번 변경 대상은 그 안내가 아니라, 기존 작업 준비·조회·입력 생성 경로가 실제 원문 읽기로 이어지도록 연결하는 것이다.

해결 방향: 준비 경로가 직접 원문을 읽는다

새 읽기 명령을 하나 더 만들거나 "이 문서를 읽으라"는 지시를 더하는 것으로는 부족하다. 그것은 에이전트에게 추가 행동을 요구하는 방식이고, 에이전트는 그 행동을 빠뜨릴 수 있다. 대신 지금 작업 준비·조회·작성 입력 생성에 쓰는 경로 자체가 원문 읽기를 수행하고, 그 반환값에 의미 본문을 포함하도록 바꾼다.

원문을 어느 실행 지점에서 작업 입력에 넣는가

비교 질문은 하나다. 원문을 어느 실행 지점에서 작업 입력에 넣을 것인가. 두 안 모두 선정한 문서의 의미 본문 전체를 전달하고, 두 안 모두 에이전트에게 별도 읽기 행동을 요구하지 않는다. 충실도가 다른 구현이 아니라 삽입 지점이 다른 선택지다.

비교 축A. 작업 확정·전환 이벤트에서 자동 전달B. 작업 준비·입력 생성에 원문 읽기 결합 권고
전달 시점작업이 확정되거나 전환되는 이벤트 직후작업 범위가 확인된 준비·입력 생성 시점
에이전트의 추가 행동없음없음
장점지원되는 이벤트가 발생하면 일관되게 전달하기 쉽다읽은 본문을 실제 입력 구성에 그대로 연결하기 쉽다
감수할 점런타임마다 이벤트 지원과 작업 식별이 다르고, 불필요한 재주입을 따로 관리해야 한다준비 경로를 건너뛰는 실행에는 적용되지 않으며, 실제로 쓰이는 진입점들을 모두 연결해야 한다
유리한 조건작업 경계가 명확하고 이벤트를 안정적으로 제어하는 환경여러 실행 환경에서 기존 준비·작성 경로를 재사용하는 환경

권고는 B다. 이미 있는 원문 추출 기능을 재사용해, 지금까지 힌트만 돌려주던 준비 결과가 본문을 포함하도록 연결할 수 있기 때문이다. 중요한 것은 새 읽기 명령을 제공하는 데서 멈추지 않고 기존 준비·입력 생성 코드가 읽기를 수행한다는 점이다. 그 대가로 실제로 쓰이는 진입점들을 하나씩 연결하는 작업이 필요하고, 이 경로를 거치지 않는 임의 실행까지는 보장하지 않는다.

에이전트에게 전달할 문서와 내용

전달 방식을 정한 다음에 오는 하위 설계 질문이다. 기본 대상은 작업의 직접 계약·목표·완료 조건, 그리고 선언된 관계로 연결된 상위 목적과 적용 제약이다. 유지보수 작업에서는 해당 영역의 현재 계약을 기준으로 삼는다.

선정 방식좋은 점부담
작업별 목록 확정입력이 고정된다작업마다 목록을 갱신해야 한다
선언된 관계 따라가기공유된 관계를 재사용한다빠진 관계는 스스로 발견하지 못한다
검색·관련성 판단등록되지 않은 근거를 찾는 데 유리하다누락과 결과 변동을 별도로 다뤄야 한다

현재 방향은 직접 입력과 선언된 관계를 기본으로 하고, 빠진 관계의 발견은 작업 준비 단계의 판단으로 보완하는 것이다. 검색으로 나온 후보는 그 자체가 승인 근거가 되지 않으며, 실제 기존 권한과 현재 계약을 확인한다.

전달하는 내용: 의미 본문 전체

선정된 문서는 의미 본문 전체를 전달한다. 다음 그림이 무엇이 읽히고 무엇이 빠지는지, 그리고 무엇이 아직 기본안 밖인지를 함께 보여 준다.

즉 기본안은 전체 의미 본문을 먼저 전달하고 문서 단위 반복 읽기를 다룬다. 절 선별과 분할을 지금 넣지 않는 이유는 그것이 불필요해서가 아니라, 실제 전달 한계 사례를 확인하기 전에는 어떤 기준으로 나눌지 정할 근거가 없기 때문이다.

원문 전달 시점과 재개 처리

앞의 선택이 실제로 적용되는 방식은 순서대로 지나가는 단계가 아니라 상황에 따라 갈라지는 동작이다. 준비 경로가 호출될 때마다 지금이 어떤 상황인지에 따라 다음 그림처럼 동작이 달라진다.

중복 제어는 문서 단위에서 시작한다. 절별 전달 상태나 복잡한 캐시를 먼저 도입하지 않는다. 언제 읽을지의 문제와 읽은 본문에서 어떤 절이 필요한지의 문제를 섞지 않는다. 또한 세션 시작 안내와 본문 읽기는 같은 행동이 아니다 — 안내는 힌트를 주고, 본문 읽기는 준비 경로가 수행한다.

예외 처리

발생 빈도는 아직 측정하지 않았다. 관찰되지 않은 발생률을 만들지 않고 발생 조건과 영향으로만 분류한다.

#발생 조건영향처리
1 진행할 작업을 식별하지 못함 작업 없는 설명 요청에서는 정상일 수 있다. 변경 작업에서는 잘못된 근거를 읽을 위험이 있다. 요청과 문서 후보를 좁힌다. 다른 작업을 임의로 인수하지 않는다.
2 필요한 계약 관계가 등록되지 않음 새 데이터·처리 경로를 다룰 때 확인이 필요하고, 놓치면 계약 누락으로 이어진다. 계약 목록과 적용 범위를 대조해 후보를 찾고, 기존 권한에 따라 관계를 보완한다.
3 문서 부재 또는 판본 충돌 잘못된 기준으로 변경할 수 있어 영향이 크다. 제공하지 못한 근거를 알리고 그 근거에 의존하는 변경을 보류한다. 무관한 읽기까지 중단하지 않고, 기존 원문과 사용자 판정은 보존한다.
4 의미 본문 전체가 전달 한계를 초과 실제 크기를 먼저 확인해야 한다. 조용히 잘라 완료로 처리하지 않고 초과 사실을 알린다. 분할이나 별도 전달 방식은 실제 사례를 근거로 후속 설계하며, 임의의 수치 한도를 만들지 않는다.

한계와 개선 효과 확인

한계: 원문을 전달한다고 해서 에이전트가 의도를 이해하고 적용하는 것이 보장되지는 않는다. 전달의 효과와 이해·적용의 효과는 별개이며, 이 제안이 직접 관찰할 수 있는 것은 앞쪽이다.

정확한 명령 인자, 저장 형식, 중복 제어 상세, 전달 한계 대응은 후속 명세와 계획이 정한다.
